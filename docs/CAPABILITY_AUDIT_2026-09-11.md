# Capability audit — 2026-09-11

Scope: focused source review of the Hub adapters, shared contracts and web controls against the schema generated by the configured Codex 0.153.4 executable. GPT findings describe our adapter, not a claim about every feature available to every ChatGPT account. This is not a complete live-device acceptance test. No real quota credits were consumed.

The ordinary work loop is substantially represented: native projects/history, model and effort selection, Codex Work/Plan and access settings, durable sends, queue/Steer, approvals/questions, interruption/recovery, attachments, generated images/files/previews, read-aloud and desktop handoff. Codex already supports an explicit thread fork. Our separate Tasks/Notes/Plans/Reports/Core are additional Hub features, not replacements for native account features.

There is no defensible single “percentage preserved”: protocol methods include infrastructure and alternative authentication flows, while one missing content renderer can affect an entire workflow. The concrete gaps below are more useful.

## High-priority gaps

1. **Some interactive Codex requests cannot complete through this client.** `mcpServer/elicitation/request` exists in the installed schema but is absent from the request allowlist. A tool that needs such a form/URL interaction is rejected. `item/tool/call` supports only the workspace-dependency lookup; other desktop-hosted tools return an explicit unsupported result. Ordinary native/MCP tool execution is not disabled. Next: implement typed elicitation and inventory actual desktop tool requests individually. Do not add a generic raw-RPC bridge. [Request handling](../apps/hub/src/sessions.ts), [workspace tool](../apps/hub/src/workspaceTools.ts).

2. **GPT drops unsupported visible content types.** Canonical history accepts only `text` and `multimodal_text`, with string/image parts and attachment metadata. Audio/video-specific messages and other native structured formats can disappear rather than show a useful placeholder. Downloads already represented as attachments remain supported. Next: retain a safe “open in ChatGPT” placeholder, then add explicitly understood renderers. [History normalization](../apps/hub/src/gpt-history.ts).

3. **Codex terminal output arrives only when the command finishes.** The adapter consumes `aggregatedOutput` at completion but not `item/commandExecution/outputDelta`. A long build can appear opaque while running. Completed output is capped at 64,000 characters without an explicit truncation marker; per-file diffs are capped at 100,000. Next: bounded live output in Activity/Results and a visible truncation/download affordance. [Event handling](../apps/hub/src/sessions.ts).

## Useful secondary gaps

4. **Native progress is richer than our progress panel.** Public reasoning summaries and plan text are supported, but structured `turn/plan/updated`, `thread/tokenUsage/updated` and aggregate `turn/diff/updated` are not projected. This loses checklist progress, context usage and a unified turn diff, not the final answer or existing per-file results. Next: small native-progress/context controls using the current shared shell. [Event handling](../apps/hub/src/sessions.ts).

5. **GPT answer branches have no custom controls.** History follows `current_node`; the web API has no edit/regenerate/branch-selection actions. Existing alternate answers are not navigable in our primary chat view. Next: native branch identities and explicit operations with the same uncertain-send protections. This does not affect Codex's existing fork action. [History](../apps/hub/src/gpt-history.ts), [GPT API](../apps/hub/src/gpt.ts).

6. **Native ChatGPT project and specialist screens remain partial.** The project projection carries identity/name, not an editor for native instructions and project files. Our Core is separate. HTML previews are not the native Canvas editor, human Tasks are not ChatGPT scheduled tasks, and read-aloud is not a two-way native voice conversation. These need their own integrations; the protected original ChatGPT page remains the fallback. [Project projection](../apps/hub/src/gpt-history.ts), [GPT API](../apps/hub/src/gpt.ts).

7. **Account information is mostly polled.** Settings refreshes limits at 60-second intervals while visible. Account-scoped `account/rateLimits/updated` is dropped by the thread-first event lookup. Earned reset credits were also absent; #129 adds them in this change. Next: invalidate the limits view on account events. Usage analytics/workspace notices are separate optional work. [Usage view](../apps/web/src/UsageLimits.tsx), [Codex events](../apps/hub/src/sessions.ts).

## Intentional exclusions

Hidden reasoning, tool internals from GPT, credentials, signed asset URLs and billing balances are deliberately not exposed. Paged history, collapsed code and media moved into Results are presentation choices, not lost functionality. Native login/token-refresh infrastructure is not counted as an end-user feature missing from the web client.

Suggested order after #129: unsupported visible-content placeholders and MCP elicitation → live command output → structured native progress/context → GPT branches and native project editing. Native voice/Canvas/automation management are larger separate features.

Owner-prioritized follow-up: [native message dictation](DICTATION.md) now uses the existing ChatGPT account's recognition route for both composers, with no substitute engine or API key. This closes draft dictation specifically; it is not a full voice conversation. Confirmed zero earned resets also get an explicit empty-state label. The other gaps above remain open.

Protocol reference: [OpenAI App Server documentation](https://learn.chatgpt.com/docs/app-server), checked alongside the installed executable's generated schema.
