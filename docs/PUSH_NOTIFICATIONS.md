# Private work notifications

Settings → Уведомления enables delivery only on the current device, after the owner taps its enable button. Both Codex and GPT use the same section and device preferences. Categories: completed work, questions/permissions, failures/uncertain work. No permission prompt runs on startup. On iPhone/iPad, Web Push requires an installed Home Screen web app and a user gesture; unsupported/denied devices retain all in-app work controls. No extra login, mail service or API billing account is required.

Notifications now show Codex/GPT, the cached project and chat names, the outcome, and a bounded excerpt of the public final answer. Questions use a non-secret public question; permission requests describe their kind without commands. Failed preparation uses exact allowlisted explanations; unknown outcomes ask the owner to check the chat/queue before retrying. Only existing Hub data is read: notifications never fetch native history, acquire a writer or generate an AI summary.

The owner requested informative notifications. Detailed display is enabled for existing and new subscribed devices; Settings → Уведомления → Показывать чат и текст ответа can hide names and excerpts on that device, retaining only the fixed status. An older client updating categories preserves that preference. Prompts, secret questions, reasoning, commands, local paths, code blocks and signed asset URLs are not used as previews. Only the opaque notice ID enters routing. Exact Codex event/turn correlation prevents a later turn's answer leaking into an earlier notice. Missing/compacted source data falls back to useful status text. GPT content comes from the exact durable job, with cached native identity and verified project associations.

Payloads retain the original fixed title/body alongside optional bounded display fields. Old service workers keep delivering generic notifications until updated; new workers validate the bounded display and fall back safely. No existing device needs to resubscribe. Push subscriptions and encryption keys remain private Hub state, inaccessible in device-status responses. The Hub accepts only HTTPS push-provider endpoints for Apple, Google, Mozilla and Windows, never an arbitrary outbound address.

SQLite migration 10 captures semantic Codex events and GPT job transitions transactionally. A small independent worker fans out to opted-in sessions, deduplicates event keys and stores delivery receipts. Closing a page does not end delivery or a task. Expired subscriptions (404/410) are removed. Known temporary provider refusals receive at most three attempts; timeouts or a process crash after an ambiguous send are not replayed. Old notices remain resolvable for 30 days; unsent deliveries expire after 15 minutes to avoid a burst of obsolete alerts. No delta/log notifications are produced.

A visible, focused chat sends a short device/tab presence lease. Suppression requires an observation after the event; a pre-event heartbeat only defers delivery until the next heartbeat or the lease expires. This avoids suppressing completion just because iOS killed a previously visible page. Other devices keep independent preferences and visibility. Resolved questions, superseded GPT warnings and deleted chats are skipped. Test delivery intentionally bypasses category/foreground suppression.

Clicking a notification focuses the existing same-origin PWA and resolves its opaque ID through an authenticated Hub endpoint; a cold start keeps the ID in the URL through login. It selects the existing Codex thread or native GPT conversation, without submitting a prompt, creating a conversation, releasing the desktop or acquiring a writer. Drafts stay with their original chat. A deleted/expired target produces an ordinary recoverable error.

Subscriptions reference login sessions and are removed when those sessions are revoked. A fresh login requires explicit re-enabling of device delivery. Native permission may remain granted by the OS; no automatic resubscription takes place. Foreground settings also revoke a disappeared or denied OS subscription. VAPID keys are generated once as `push-keys.json` beside the database, mode 0600. Backup includes them as `private/push-keys.json`; restore places them beside the restored database. Restoring still revokes sessions and therefore subscriptions. Key-file failure disables optional push without preventing the Hub or its jobs from starting.

## Verification

`tests/push.test.mjs` covers auth/CSRF, provider restrictions, transaction capture, deduplication, restart, semantic statuses, per-device presence, category filters, stale/deleted targets, revocation during delivery, retries, expiry, private keys, and service-worker click routing. The shared settings and full app run in Chromium/WebKit with mocked browser permission/subscription APIs and real isolated Hub contracts: direct gesture opt-in, no automatic prompt, preferences, revocation, cold/warm navigation, Codex draft preservation, GPT target selection, and no writer acquisition. These browser tests do not claim real APNs delivery or a physical iPhone/iPad acceptance pass.

After installation, the owner enables notifications on their iPhone/iPad and uses “Проверить уведомление”, then checks completion while the PWA is closed. System Focus modes and device notification settings continue to control presentation. References: https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/ and https://github.com/web-push-libs/web-push.

## Long native history regression (Books)

Read-only measurement on the owner's Books conversation showed ~7.5–8.5 seconds per native `thread/turns/list` call. Filling a 20-message tail with several calls exceeded the browser's 30-second read timeout. History now uses a five-second collection budget checked between native pages, returning up to 20 available messages and an intact older-history cursor. It never cancels or forks the native conversation. Empty technical pages also retain their cursor. Concurrent identical history reads stay coalesced for the entire pending request, with cache TTL starting after completion. The real Books tail returned five messages in 8.3 seconds with one native turn read; older messages remain explicitly loadable. Two regression tests cover order/cursor preservation and long in-flight coalescing.
