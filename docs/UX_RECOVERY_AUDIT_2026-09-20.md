# Аудит восстановления и лишних действий — 20 сентября 2026

Правило владельца: сначала тихо восстановить, только после неудачи объяснить проблему и предложить действие. Статус внутренней реализации не должен становиться пользовательской задачей.

Это аудит кода и целевые браузерные проверки, не полная аппаратная приёмка iPhone/iPad.

## Что уже восстанавливается автоматически

- useWorkspace: WebSocket с backoff, возвращение сети и вкладки; сохранённая история при недоступном ПК.
- useGptHistory: периодическое чтение, online/pageshow/visibility, сохранённый кэш.
- GPT каталог/модели: несколько тихих попыток перед loadNotice.
- MessageQueue: ошибки чтения показываются после нескольких неудач, healthy snapshot очищает их.
- Передача загрузок: существующие подтверждённые фрагменты и квитанции; не превращать retry фрагмента в отправку нового сообщения.

## Ручные действия, которые остаются осмысленными

- Неизвестный исход отправки: сначала проверка канонической истории/квитанции; без слепого повторного send.
- «Вернуть в черновик» и конфликт с новым текстом — выбор владельца, не сетевой retry.
- Восстановление версии Canvas/Core, удаление, сброс лимита, запуск плана, публикация, смена владельца исполнения и жёсткий рестарт — реальные изменения, не восстановление связи.
- Вход, bot challenge, согласие, истёкшая авторизация, отсутствие разрешений/исходника и конфликт редакций требуют понятного адресного действия.

## Проверки этого захода

- Целевой тест общей retry-политики: один повтор чтения, без повторной записи/ошибок доступа/rate limit/предметных ошибок; отмена и смена сессии.
- Очередь GPT: пустой чат, работа другого чата, предыдущая running/unknown работа своего чата, завершённая работа.
- Chromium/WebKit: автоматическое подключение Codex, отсутствие плашки в процессе/после успеха, ручной retry после ошибки, сохранение черновика, отсутствие turn/start и restart.
- Сборка Linux. Загрузки крупных файлов и широкие несвязанные тесты не повторялись.


## Второй заход: переподключение и сохранение экрана

- DeviceTerminal: три ограниченные фоновые попытки повторного подключения к тому же ID и живому PTY. Новый shell не создаётся; ввод не повторяется. Кнопка скрыта при здоровом соединении, после exit нет перезапуска. 1008/ошибки доступа не запускают цикл. Online/возврат страницы помогают восстановить потерянное соединение.
- Пока терминал переподключается, показан прежний экран; после подтверждения сервер переотдаёт сохранённый ограниченный буфер. Он заменяет экран, а не добавляется повторно. Не обещаем неограниченный scrollback: сервер и ранее сохранял только ограниченный буфер.
- Remote ПК: до трёх тихих попыток с увеличением паузы, отдельный таймаут первого кадра. Счётчик сбрасывается после устойчивого соединения, а не каждого краткого connect. 769/771 требуют ручного действия. При сворачивании отпускаются ввод/клавиши и соединение; при возврате возобновляется только открытый пользователем Remote. Явное закрытие сохраняется. Ручная кнопка действительно переподключает, без второго нажатия.
- Results: тот же набор остаётся при повторной загрузке и её ошибке. При смене проекта/категории данные очищаются. Git-diff и ссылка на сохранённый файл сохраняются при обновлении того же выбора; другой выбор их очищает.
- Файловый список и Notes уже сохраняли данные при обновлении того же scope — подтверждено чтением кода, лишние изменения не внесены.
- Отдельная серверная страница GPT `ops/gpt/connect-client.js` пока сохраняет прежнее поведение. Её выпуск относится к отдельному GPT runtime, не к UI Remote ПК; не перезапускать его ради этого во время работы.
- Целевые Chromium/WebKit проверки: реальный Hub/PTY fixture и WebSocket-разрыв, один shell и один ввод; завершение и отказ доступа; Remote разрыв/сворачивание/возврат/закрытие с имитацией Guacamole; сохранённый draft; Results остаётся при ошибке и медленном retry. Это не аппаратная проверка удалённого ПК.



## Скриншот IMG_0511: временная недоступность истории

- Нативная ветка подтвердила точный текст со скриншота, промежуточное сообщение и завершённый ответ. Квитанция Hub тоже completed. История восстановилась; исходная причина краткого сбоя не установлена. Повторная отправка не нужна.
- useGptHistory больше не показывает предупреждение при первом временном сбое с доступной историей. Оно появляется после минимум трёх неудач и 30 секунд, исчезает после успешного чтения. Частота запросов не увеличена, признак stale сохранён.
- Ошибки доступа, отсутствие истории и ошибки явного открытия старой страницы/источника видны сразу. Убран внешний catch, повторно выставлявший обработанную ошибку.
- Chromium/WebKit: восстановление, длительная ошибка, отказ доступа, сохранение текста/черновика, отсутствие записывающих запросов. TypeScript проверен на Linux.

## Готовность кнопки отправки GPT

- При первой загрузке поле ввода остаётся видимым и принимает черновик. Кнопка заблокирована и показывает кольцо до готовности истории выбранного чата, подключения и модели. При известной ошибке кольцо прекращается; существующие сообщения восстановления остаются доступны.
- Общая готовность применяется к кнопке, обработчику отправки и диктовке. Уже загруженный чат не блокируется при фоновом обновлении истории; дополнительных проверок нативного клиента нет.
- Chromium/WebKit: задержанная история и модели, доступность черновика, запрет преждевременной отправки, разблокировка и отсутствие кольца при фоновом чтении. TypeScript проверен; lint по изменённому компоненту содержит прежнее замечание useSemanticElements к gpt-recovery-conflict.
- Публикация только UI, без перезапуска GPT/Codex.

## Прогресс отправки и ссылки (IMG_0512 / IMG_0513)

- Панель прогресса появляется сразу при отправке, остаётся на начальных queued/preparing стадиях с подписью «Отправляется» и переходит в «GPT работает». «В очереди» показывается только при реальной предыдущей работе того же чата.
- Быстрые ответы readSubmission/readConversation теперь преобразуют публичные citation/URL-маркеры по metadata, как каноническая история Hub. Пользовательский текст и проверка точной доставки не меняются. Никаких дополнительных запросов истории или обхода скрытых сообщений.
- Ссылки sandbox из быстрых ответов разрешаются через IDs сообщений в сохранённой нативной квитанции того же чата. Нельзя подставить квитанцию другого диалога или угадать файл по имени; неоднозначный результат не выбирается автоматически.
- Внешняя HTTP(S)-ссылка из Markdown Codex/GPT запрашивает отдельное окно браузера с noopener/noreferrer. На iOS представление окна контролируется Safari. Якоря остаются на текущей странице; файлы/картинки идут через существующий Results resolver. Внешние сайты не встраиваются в iframe приложения.
- Проверено: TypeScript/сборка Linux; нативное преобразование источников без повторного чтения; Hub resolver canonical/job IDs и отказ для другого чата/файла; Chromium/WebKit — непрерывный прогресс, точные результаты/картинки, недоступный источник, внешний popup, сохранение черновика/вложений на телефоне/планшете/ПК. Большое скачивание в этом прогоне пропущено явно (ARTIFACT_LINKS_ONLY).
# GPT drawer responsiveness follow-up

- Opening the drawer does not fetch the whole catalog: GPT reads 20 conversations per page and retains the loaded list. A live read measured about 2.3 seconds for the first page and 3.1 seconds for projects; these reads remain background work when a list is already available.
- Found a separate rendering regression: the inline artifact callback invalidated memoized reply Markdown on every drawer/composer update. Cache the rendered Markdown by text and link capability while retaining the latest committed artifact callback. Do not cache stale conversation/file bindings.
- The focused navigation browser check failed on the previous code because unchanged link nodes were recreated. With the fix, Chromium and WebKit retain text/link nodes, drafts and exact artifact navigation across repeated offline drawer opens, with no extra catalog requests. Repeat opens measured 50–100 ms in the fixture; first WebKit open was about 1.3 seconds. These are simulated-browser observations, not iPhone hardware acceptance.
- The preceding `c24a506` engine/UI release is confirmed installed. This follow-up changes only web rendering and can be published without restarting Codex/GPT.
